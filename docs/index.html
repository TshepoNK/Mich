The Problem

UI testing is expensive,
brittle, and exclusive

QA teams face the same fundamental problems regardless of which tools they reach for.

💔

Selector Brittleness

A single design sprint can invalidate hundreds of test files. SDETs spend days in "selector archaeology" after every UI refactor.

🚧

High Floor for Non-Coders

Manual QA testers with years of domain knowledge are excluded because they can't write TypeScript async/await. The tools fail their most valuable users.

⏱️

Authoring Is Expensive

An experienced engineer spends 2–4 hours writing a single reliable checkout test. Recorders generate code that breaks in 6 months.

🎲

Flakiness Has No System-Level Fix

retry() and waitFor() are band-aids. Teams disable flaky tests rather than fix them, creating a false safety net.

🔧

Maintenance Grows With Velocity

At scale, test maintenance consumes 30–50% of automation time. The faster the team ships, the more tests break. There is no structural answer.

🤷

No Business Intent

Playwright knows nothing about what a test means. A payment failure and a CSS class change look identical — both produce a red test and a stack trace.

How it works

Describe goals. Agents do the rest.

Mich Orion decouples the intent of a test from the implementation. The goal is permanent. The execution strategy adapts.

1

Write a goal

Use plain English, YAML, or Gherkin. Describe what the user should be able to do — not which elements to click. No code required.

2

Agents execute it

Four specialized agents — Orchestrator, Flow, Observe, and Memory — collaborate to navigate, assert, monitor network traffic, and learn from every run.

3

Get a Failure Brief

When something breaks, you get an incident-style report: what failed, why it's an app bug (not a test issue), and which PR likely caused it.

Test Authoring

Two formats. Zero JavaScript.

Write tests in YAML or Gherkin-style natural language. Both formats compile to the same goal spec — a structured intent description that the agent swarm executes.

Features

Built for resilience, not just automation

Every capability was designed around a real failure mode in traditional test frameworks.

🧠

Multi-Strategy Resolution

Elements are found via aria-label → role+name → label-for → placeholder → visible-text → DOM hint. The fragile CSS selector is always the last resort, never the first.

💾

File-Backed Memory

Every successful resolution is fingerprinted to .orion/memory/<test>.json. Future runs use the strategies that already worked, eliminating cold-start fragility.

📡

Network Observation

XHR and fetch traffic is recorded alongside every step. Assertions can target network outcomes — "POST /api/orders returned 201" — eliminating race-condition flakiness structurally.

🩺

Failure Brief

Incidents are reported like a post-mortem: what failed, why it's an app bug vs test drift, which JS error fired, and which recent PR is the likely culprit. No stack traces.

🔮

Flakiness Detection

After enough runs, recurring failure signatures are automatically flagged as patterns — not isolated failures. The system learns that step 3 flakes at 2:30 PM UTC in CI and tells you why.

⚡

LLM-Powered Briefs

With an Anthropic API key, failure briefs are written by Claude Sonnet 4.6 with prompt caching. Without a key, you still get a fully structured deterministic brief.

Self-Healing

Selectors become irrelevant

Mich Orion stores a multi-modal element fingerprint — not a CSS selector. Each interactive element is known by its aria role, visible text, screen region, and network trigger.

Strategies are ranked by a confidence score. When the developer renames a component, the agent tries the next strategy, succeeds, updates its strategy map, and the test stays green. CI never sees red.

1

Primary strategy fails

CSS selector .checkout-btn not found — developer refactored the component.

2

Agent escalates to text strategy

Locates button with visible text "Complete Purchase" in the expected screen region. Confidence: 0.97.

3

Test passes. CI stays green.

Memory Agent logs the stale selector, promotes text strategy. A low-priority notice is queued for the team.

Incident reports, not stack traces

When a test fails, Mich Orion doesn't show a wall of JavaScript. It writes a structured report that tells you what broke, why it's a real bug, and who likely caused it.

Architecture

Four agents. One goal.

Mich Orion's multi-agent architecture separates concerns that traditional tools conflate: navigation, assertion, observation, and learning.

Tier 1
Orchestrator Agent
Receives test goal + app context → produces execution plan, agent assignments, and priority order
↓
🧭
Flow Agent
Navigates the UI to reach the goal — resolves elements, performs actions, handles retries
✅
Assert Agent
Verifies outcomes against intent — distinguishes cosmetic changes from functional regressions
📡
Observe Agent
Monitors XHR/fetch traffic, console errors, and performance during every action
↓
Persistent Layer
Memory Agent
Stores learned strategies, failure patterns, and timing heuristics — gets smarter with every run

test('user can reset password', async ({ page }) => {
  await page.goto('/login');
  await page.waitForLoadState('networkidle');
  await page
    .locator('[data-testid="forgot-link"]')
    .click();
  await page.waitForURL('**/forgot-password');
  await page
    .locator('#email-input')
    .fill('test@example.com');
  await page
    .locator('[type="submit"]')
    .click();
  await expect(page
    .locator('.success-message'))
    .toBeVisible({ timeout: 5000 });
});

Get Started

Up and running in 3 steps

No account required. No cloud signup. Runs entirely on your machine with Chromium.

Step 1 — Install
$ npm install @mich/orion
Step 2 — Install Chromium
$ npx playwright install chromium
Step 3 — Run an example
$ npx orion run examples/example-domain.orion.yaml
Add --headed to watch the browser. Set ANTHROPIC_API_KEY for LLM-powered failure briefs.
Step 1 — Install
$ pnpm add @mich/orion
Step 2 — Install Chromium
$ pnpm exec playwright install chromium
Step 3 — Run an example
$ pnpm exec orion run examples/example-domain.orion.yaml
Step 1 — Install
$ yarn add @mich/orion
Step 2 — Install Chromium
$ yarn playwright install chromium
Step 3 — Run an example
$ yarn orion run examples/example-domain.orion.yaml
✦ Optional — LLM failure briefs. Set ANTHROPIC_API_KEY=sk-ant-... before running. Without it, you still get structured deterministic failure briefs — just not AI-authored.
